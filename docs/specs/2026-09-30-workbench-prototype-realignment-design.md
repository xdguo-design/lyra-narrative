# NarrativeOS 原型工作台重整设计

## 状态

待用户评审；确认前不实施代码变更。

## 背景与目标

用户提供的 Novel Workbench 原型是本轮界面的目标基准。它把章节工作流放在中心，以全局导航切换工作区域，并在右侧持续展示当前章节上下文。现有页面则固定为“作品/章节侧栏 + 正文编辑器 + 创作辅助标签页”。模型配置、人物管理、AI 输出被塞在窄侧栏的标签中，任务也只显示卡片列表，无法呈现原型的任务流主视图。

本轮目标是将现有工作台重整为原型的信息架构，让任务流成为默认落点，同时继续使用现有真实数据、编辑和任务操作。不能为了视觉匹配而把数据库中不存在的场景规划、专项编辑或评审专家节点显示成正在运行的真实任务。

## 已有能力与边界

- 章节有持久化标题、正文、状态、字符数、自动保存和版本历史；正文仍由专用编辑器编辑。
- 写作任务有目标、补充指令、章节关系、状态、Skill 策略和多条 Agent Run。运行记录包含角色、阶段、状态、模型、耗时或错误信息；任务详情可轮询读取。
- 当前真实工作流是 Writer → 多个 Reviewer → Revision，修订稿待人工批准后才写入正文。
- 模型 Provider 支持新增、编辑、删除、设为默认、协议/模型/Base URL/Key 环境变量名配置。真实 Key 继续只通过环境变量读取。
- 人物卡目前有作品隔离的列表和新增能力；后端当前提供 list/create，没有人物更新或删除接口。本轮可先保留已有管理能力，人物编辑/删除需另行补 API 与数据操作设计。
- AI 续写、润色和一致性检查结果保存在辅助面板，并有追加/替换正文操作。
- 当前页面没有截图原型中的独立任务 DAG 数据模型，也没有每个章节目标、场景规划、多个专项编辑与整合节点的持久化状态。

## 方案

采用完整工作台信息架构重整，不做只叠加一张 DAG 的局部页面。保持 FastAPI API 和数据库语义不变，主要调整静态页面结构与前端页面状态；需要新增持久化阶段或真实场景级 DAG 时，再作为后续后端功能提出。

### 桌面布局

1. **左侧全局导航**：品牌、作品概览、章节任务流线、AI 编辑、多角度评审、角色知识库、小说资料库、技法知识库、风格设置、模型与技能、设置。当前实现有真实对应能力的入口可直接启用；未实现的区块使用清晰的空态/可用性说明，不伪装成已有模块。
2. **中央主工作区**：默认选择“章节任务流线”，展示当前作品、当前章节、章节目标和该章节的真实写作任务/Agent Run 流程。保留全局任务创建、运行、详情和审阅确认入口。
3. **右侧章节上下文**：章节状态、优先级/字数（仅采用系统已有值）、正文摘要或目标、任务统计，以及“AI 输出”结果卡片。无输出时显示空态；生成完成后在此处呈现完整可读结果，并保留追加/替换正文动作。人物或模型配置页面切换时，右侧栏可收起为这些页面留空间；章节任务流与 AI 输出状态不能因导航切换丢失。

### 导航与编辑行为

- 首次进入或刷新后以“章节任务流线”为默认工作区；当前选择的作品和章节仍由已有选择状态驱动。
- 从任务流节点打开任务详情，并在同一工作区呈现运行记录、错误、草稿、评审发现和审批动作；运行中持续更新真实状态。
- 章节正文编辑以“AI 编辑”工作区承载，提供已有编辑器、AI 动作、输出预览、追加/替换与版本历史。可从 DAG 章节节点跳转到该编辑器。
- 模型与技能入口聚合现有 Provider 和 Skill 能力。模型表单和 Provider 增删改/API 保持现状。
- 角色知识库入口展示当前作品人物卡及创建入口。因当前 API 仅支持创建和列表，界面不提供无法持久化的编辑/删除承诺；如本轮要求完整 CRUD，则需把相应 API 变更纳入单独审批的范围。
- 浏览器前进/后退是否使用 URL hash 保存工作区/选中章节，作为实现细节优先沿用当前无路由应用的简单状态；若无障碍导航/刷新恢复无法满足，再引入 hash，不新增服务端路由。

### 第一阶段 DAG 的真实数据映射

- **章节目标节点**：对应章节标题/已存在的创作目标；没有章节目标字段时展示中性章节卡片，不生成虚构状态。
- **写作任务节点**：每个节点对应一条 writing task，显示真实 goal、status、关联章节和创建时间。
- **执行子节点**：任务详情中的每条 agent run 映射为 Writer、Reviewer、Revision 等执行节点，按实际 run 顺序连接；名称使用记录的 role/stage，状态用记录状态。
- **连线**：只代表当前工作流中已知的顺序/依赖。若后端只记录顺序，使用有序链路，不画出并行分叉或原型中的每种专项编辑。
- **尚无运行记录的任务**：显示一个待运行任务节点，不凭空补出 Agent Run。
- **失败、等待审批、完成**：分别使用状态标签/图例；颜色之外同时显示文字/图标，保证可读性。
- **任务数据装载**：用已有项目任务列表 `/api/projects/{project_id}/tasks` 取卡片；选中或轮询任务时用 `/api/tasks/{task_id}` 获取 runs 等详情。初版不新增 API、表或迁移。

## 方案比较

| 方案 | 内容 | 取舍 |
|---|---|---|
| A. 整体恢复原型信息架构（推荐） | 默认章节任务流，左侧全局导航，右侧章节上下文，保留现有编辑器和配置能力 | 与原型和用户指出的问题一致；前端重排范围较大，但不必改动工作流数据层 |
| B. 仅在现有三栏布局增加 DAG 面板 | 保留当前章节侧栏、中央编辑器和右侧 tab，只添加任务流视图 | 交付较快；导航层级仍与原型不同，模型/人物/输出仍然埋在辅助栏中 |
| C. 直接照图完整模拟所有节点 | 同时绘制场景规划、专项编辑、整合、9 类评审和最终输出 | 视觉上更像截图，但当前持久化工作流没有这些阶段，会把设计示意误报成真实进度；不建议 |

## 验收标准

- 桌面首次打开时，主视图是原型风格的章节任务流工作区，而不是固定三栏编辑器。
- 用户能从左侧明确进入任务流、AI 编辑、角色知识库、模型配置、技能等真实工作区。
- 任务流仅呈现真实任务和 Agent Run；任务状态、角色、模型、错误、运行中刷新以及待审批状态均能从现有 API 还原。
- 右侧章节信息明确反映当前选中章节；AI 结果在生成后完整可见且追加/替换操作可达，不再依赖滚动隐藏的辅助标签。
- 角色列表/创建、Provider 新增/编辑/删除/设默认、现有 AI 编辑功能仍可使用；不能支持的模块以明确空态呈现。
- 页面刷新后作品/章节和工作区行为清晰一致；原有正文、版本、任务和 Provider 数据不丢失。
- 在桌面、平板及手机视口中，主导航可收纳/展开，主工作区和关键操作可达，无不可见的模型、人物、任务或输出区域。
- 已有浏览器写作流程继续可以创建章节、保存正文、创建并运行写作任务、查看真实运行进度、审批修订，并检查正文版本持久化。

## 不在本轮范围

- 增加原型图中尚未存在的 Planner、专项编辑器、人工/AI 评审类型或新的工作流阶段。
- 修改 Provider 路由策略、AI prompt、Writer/Reviewer 执行逻辑或 SQLite schema。
- 将 AI 输出自动写入正文；仍由用户明确追加或替换，任务修订稿仍由人工审批后写入。
- 人物编辑/删除的后端 CRUD（待用户确认是否需要纳入本轮）。
